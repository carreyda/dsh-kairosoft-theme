# 开罗物语 · 双主题

DeepSeek Harness 主题设计说明 · v0.2.0

参考素材：《温泉物语2》冬日营业宣传图（1670×942）、《住宅梦物语》搬家宣传图（1080×608）。

---

## 0. 摘要

两张图各给了三种温度：温泉图的**室外冷蓝雪夜**、**室内暖木灯光**、**灯笼的橙**；住宅图的**奶油墙**、**焦糖木**、**正午阳光的黄**。
主题没有去「复刻」画面，而是把它拆成三件事：

1. **图是背景，不是贴纸**——画铺在窗口最底层，面板半透明浮在画上，越靠边越能看到雪、水、纸箱和沙发。
2. **冷暖各成一个模式**——浅色=室内（米纸、木色、柿子橙），深色=室外（夜靛、暖白、灯笼黄）。不是把浅色调暗，是换了一套光。六套主题（雪夜温泉 / 暖屋搬家 / 王国冒险 / 夏水乐园 / 新年百货 / 雪场缆车）共用这套「明暗＝冷暖」的骨架，各自换色相。
3. **形状贴着走**——2–8px 小圆角、1px 硬描边、无模糊投影，靠近游戏 UI 的纸片感，而不是现代 SaaS 的玻璃感。

## 1. 从参考图读到的三件事

| 观察 | 依据 | 决定 |
| --- | --- | --- |
| 冷暖面积接近 | 夜空 `#3A4B6D` 与室内暖光 `#F6B963` 各占画面约三分之一 | 明暗两个模式分别站在冷、暖两端，而不是同一个色板调亮调暗 |
| 层次靠线不靠明度 | 木梁、窗格、石板、纸门都是 1px 深色描边分隔 | 所有面板统一 1px 描边（正文色 10%–38%），投影用 1–4px 无模糊实体偏移 |
| 橙色只做点睛 | 标题橙 `#FCBE67` / 描边 `#FA9427` 面积不到 5% | 主色只出现在发送、选中、焦点、链接、进行中状态；大面积留给中性色 |

## 3. 形状与材质

| 项 | 规则 | 令牌 |
| --- | --- | --- |
| 圆角 | 2 / 3 / 4 / 6 / 8 / 6，小控件到面板逐级放大 | `radius-xs…panel` |
| 描边 | 1px，正文色 10% / 17% / 27% / 38% 四级 | `border-l1…l4` |
| 投影 | 1–4px **无模糊**实体偏移；浅色棕 12%，深色黑 45% | `shadow-lv1…lv3` |
| 浮层 | 菜单与提示不做毛玻璃 | `menu-backdrop-filter: none` |
| 焦点 | 2px 主色环 + 2px 间隙 | `focus-ring-*` |
| 选中文本 | 主色 26% 叠加，文字色不变 | 插件内置 CSS |

圆角为什么这么小：参考图的木框、石板、窗格几乎全是直角，只有灯笼和石头是圆的。8px 已是上限。

投影为什么不用模糊：模糊阴影是「浮起来」，实体偏移是「贴上去」。图里的标题、木牌都是后者，更手绘、更像像素画。

## 4. 背景图层

### 4.1 结构

```
body            背景图（cover，固定，取景偏上 38%）
└─ .frame       透明（原先铺 sidebar-fill / bg-base）
   ├─ .sidebarCol   rgba(sidebar, 78% / 80%)
   ├─ .centerCol    rgba(bg, 80% / 84%)     ← 对话区
   └─ .bottomRow    rgba(bg, 80% / 84%)     ← 输入区
```

### 4.2 关键教训：三层半透明会互相抵消

第一版把薄纱压在 body 上（88%），面板再留 92%，结果画只剩 **1%**：

```
(1 − 0.88) × (1 − 0.92) ≈ 0.01
```

而且 `.frame` 自己也会铺一层底，列再铺一层，**相乘**之后画面就彻底没了。正确做法是：

- **body 只负责铺图，不加纱**；
- **`.frame` 变透明**（`[class*="_frame"]{background:transparent!important}`），让每个列自己承担不透明度；
- 不透明度写进令牌：`bg-base` 80% / 84%，`sidebar-fill` 78% / 80%，于是主区看到约 20% 的图、侧栏约 22%。

### 4.3 取景与体积

- `background-size: cover` + `background-position: center 38%`：把温泉池和灯笼留在可视区，裁掉顶部夜空和底部雪地边缘。
- `background-attachment: fixed`：滚动内容时画不动，像透过窗户看外面。
- 图片压到 1600×903 / JPEG q82（290 KB），base64 内联进 `client.js`，成品 396 KB，仍是单文件、离线可用。

### 4.4 窗口拖拽条

窗口最上方那条拖拽区（含最小化 / 最大化 / 关闭）属于页面，但应用本身不铺底色，于是背景图在那里 **100% 直出**，比下面每一层都亮，看着像「没盖住」。

修法是给它补一层与侧栏同源的薄纱：

```css
body::before { height: var(--kairosoft-titlebar, 0px); background: color-mix(in srgb, var(--dsw-specific-sidebar-fill) 92%, transparent); }
```

`--kairosoft-titlebar` 由运行时测量，依次取：

1. `navigator.windowControlsOverlay.getTitlebarAreaRect().height`（窗口控件覆盖模式）；
2. `--dsh-windows-titlebar-height`（应用自己声明的内边距）；
3. 都没有则 0（不铺，保持原样）。

监听 `resize` 与 `geometrychange` 重测，`pointer-events: none` 保证不挡拖拽。

### 4.5 可调控件

面板不透明度、侧栏不透明度、取景位置都会因人而异，所以做成运行时可调，而不是写死在令牌里：

- 右下角一枚灯笼按钮（`.kf-fab`，半透明，悬停变亮）；
- 面板三根滑杆 + 「显示背景图」/「侧栏与主区同色」/「柔和阴影与底部渐隐」三个开关 + 「恢复默认」；
- 取值存 `localStorage['kairosoft-theme:settings']`，默认 `{ theme: "onsen", artwork: true, panel: 84, sidebar: 80, focus: 38, linkSidebar: true, softShadow: false }`；
- 调整时只对 5 个「面板类」令牌做 alpha 平移（`bg-base`、`layer-1`、`layer-2`、`markdown-code-block`、`sidebar-fill`），再调一次 `overrideTokens`，其余 161 条令牌保持设计值。

侧栏默认**跟随主区**：直接复用 `bg-base` 的颜色与 alpha，侧栏滑杆置灰。因为 `sidebar-fill` 本身就比 `bg-base` 暗一档（深色是 `#101620` 对 `#141A24`），再叠加 `border-right` 的视觉分割，关掉「跟随」时侧栏会比主区明显更沉。想要木质侧栏时再关掉开关单独调。

柔和阴影**默认关闭**：输入区用的是 `--dsw-elevation-soft`（`0 4px 16px` 之类），侧栏底部还有一条 24px 的 `.scrollFade` 渐变。面板不透明时它们只是普通的浮起感，一旦面板变成 84% 半透明，阴影就透过面板显出来，看着像一块抹不掉的脏影。关闭时把 `--dsw-elevation-panel/prominent/soft` 压成 `--dsw-elevation-stroke`（只留 1px 描边），并把 `[class*="_scrollFade"]` 的背景清掉；想要原生的浮起感就打开开关。

### 4.6 主题包与切换

配色不止一套，所以 `design/themes.json` 从「一个调色板」升级成「一组调色板」：

```json
{ "themes": { "onsen":   { "label": {...}, "artwork": "...", "light": {...}, "dark": {...} },
              "home":    { "label": {...}, "artwork": "...", "light": {...}, "dark": {...} },
              "kingdom": { "label": {...}, "artwork": "...", "light": {...}, "dark": {...} } } }
```

- 每个主题各自派生 166 条令牌与各自的背景图，构建时全部内联进 `client.js`（六套约 1.8 MB，背景图统一压到 1440×810 / q80）；
- 面板顶部七选一：**雪夜温泉 / 暖屋搬家 / 王国冒险 / 夏水乐园 / 新年百货 / 雪场缆车 / 默认**；
- 「默认」不是第三套配色，而是 `NATIVE = null`：调用 `overrideTokens` 返回的 disposer，把覆盖摘掉，DSH 原生令牌原样回来，同时移除页面底色变量。**不注册、不残留**，这条路径和禁用插件时的还原是同一条；
- 切换会重走一遍 `syncTokens()` → 新的 `overrideTokens`，页面底色用 `--kairosoft-page-bg` / `--kairosoft-page-bg-dark`（取调色板的实色 `bg`，因为令牌本身带 alpha，单独当页面底色会透出窗口本身）。

### 4.6.2 面板自己的配色

调试面板早期借用 DS 的别名令牌（`--dsw-alias-text-primary`、`--dsw-alias-brand-text` 之类），结果在 0.2.x 上直接翻车：这些名字在当前版本里有的不存在（只存在 `label-*` 系列），有的同名不同义（`brand-text` 是「主色文字」而不是「主色上的文字」），于是深色面板上出现了深底配深字。

现在改成构建期从调色板派生一套**不透明**的面板配色，随主题与明暗注入 `--kf-panel` / `--kf-text` / `--kf-muted` / `--kf-line` / `--kf-accent` / `--kf-on-accent` / `--kf-raised`，面板 CSS 只认这套变量，带硬编码兜底。选中按钮的小字还过一道对比度闸门：反白字对强调色不足 4.5:1 时，把强调色往正文色方向推，直到达标——暖屋搬家的浅色强调色就是因此从 `#C05A38` 变成 `#B45636`。

### 4.6.1 明暗切换

调试面板第二行是 **浅色 / 深色 / 跟随系统**三挡。它不碰本插件的令牌，而是调用主题服务的 `setTheme('light' | 'dark' | 'system')`——`light` / `dark` 是 DSH 的内置主题（`BUILTIN_THEMES`），`system` 也合法，调用后会把值写回外观偏好字段并广播，所以**重启后仍然记得**，也等同于在设置里改外观。当前值从 `ctx.theme.getTheme().preference` 读，点击后重新刷 `aria-pressed`；旧运行时的实例没有 `setTheme` 时整段静默跳过，不报错。

这一行永远可用（不随「默认主题」置灰），因为它控制的是 App 外观，不是这套配色。

### 7.2 生成管线

```
palette.json ──build.mjs──▶ client.js（166 tokens + CSS）
                        ├─▶ docs/design/tokens.json（可查表）
                        └─▶ docs/design/mockup.html（浏览器预览）
```

派生规则集中在 `build.mjs`：边框=正文色 α，交互底=主色 α，状态软底=`mix(状态色, 底色, t)`，提示条反色；改配色只改 `palette.json`。

### 7.3 运行时

`src/runtime.js` 是手写的那一半（可读、可测），`build.mjs` 只负责把令牌表和 CSS 填进占位符：

```js
// src/runtime.js
window.__ModuleLoader__.load({
  id: 'dsh-kairosoft-theme',
  factory() {
    const BASE_TOKENS = __TOKEN_TABLE__;   // 构建时替换
    const CSS_TEXT = __CSS_TEXT__;         // 构建时替换
    const mount = (ctx) => {
      const settings = readSettings();
      const syncTokens = () => ctx.theme.overrideTokens('dsh-kairosoft-theme', tokensFor(settings));
      ctx.effect(() => { /* style + syncTokens + 测量拖拽条 */ }, 'kairosoft-theme: styles');
      ctx.effect(() => { /* 灯笼按钮 + 面板 */ }, 'kairosoft-theme: panel');
    };
    return { inject: ['theme'], apply: (ctx) => mount(ctx) };
  },
});
```

- `overrideTokens` 要求每条令牌都给出 `{ light, dark }`，单值会抛 `TypeError`；改滑杆时先释放上一个 disposer 再重新下发。
- 两个 `ctx.effect` 各返回一个 disposer，禁用插件时自动还原 DOM 与颜色，不留残色。
- 主题跟随后台 Appearances 的 `light / dark / system` 三档，不注册第三方主题 id（设置 schema 只接受这三个值）。
- 面板是原生 DOM，样式全部引用主题令牌变量，所以浅色 / 深色下自动同色系。

## 8. 取舍与风险

| 取舍 | 理由 | 风险 |
| --- | --- | --- |
| 只用 `overrideTokens`，不 `register` | 注册的主题 id 无法被设置持久化 | 只能跟随三档外观，不能单独命名一套主题 |
| 背景图内联为 data URI | 单文件、离线、无路径问题 | `client.js` 涨到 396 KB；换图要重新构建 |
| `[class*="_frame"]` 选择器 | 框架层必须透明，否则画被压没 | 类名后缀若在升级中改名，需要同步修改 |
| 面板保留 80%/84% | 保证深色模式在雪地高光上仍过 AA | 画只透出两成，观感偏「隐约」 |
